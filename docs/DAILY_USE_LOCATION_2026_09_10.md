## Устранённый разрыв

Новая проверка смены требует координаты участка, но в интерфейсе их нельзя было задать. API принимал их только при PATCH, а `mapSection` отбрасывал координаты из ответа. Пустые строки и `null` также могли обходить корректную проверку местоположения.

- Создание и редактирование участка содержат широту, долготу и радиус. Координаты можно ввести вручную, включая десятичную запятую, либо получить с устройства, находясь на участке.
- Неточная GPS-точка и отказ разрешения не заменяют введённые значения. Определение координат не сохраняет участок автоматически.
- API принимает координаты при создании и обновлении, проверяет диапазоны, отклоняет пустые/null/логические значения. Координаты изменяются только парой. Радиус: 10–5000 м; прежний радиус 150 м по умолчанию сохранён.
- Существующие координаты отображаются после перезагрузки. Изменение местоположения сохраняет прежний QR. Код участка и исторические данные не меняются.
- Участок можно сохранить без координат для последующей настройки. В списке и на экране QR работник видит причину недоступности смены. После настройки можно обновить данные без повторного входа.
- Миграция БД для этого изменения не требуется: используются существующие поля.

## Проверки

Локально пройдены API/web production build, 56 unit-тестов, проверки ролей/действий, 4 проверки преобразования координат и typecheck серверных E2E. Для нового поведения подготовлены PostgreSQL E2E и браузерные тесты desktop/mobile: реальная форма, отказ и неточность GPS, повторное чтение, редактирование и сохранность QR. Результат нового CI фиксируется после его выполнения.

Первый CI [34513179596](https://github.com/talgat-maratuly/gp-work-/actions/runs/34513179596) подтвердил 56 unit и 4 PostgreSQL E2E, но обнаружил перекрытие кнопки сохранения полями координат на мобильном экране. Форма редактирования исправлена: местоположение и действия вынесены из общей сетки, для узкого экрана явно задан один столбец. Браузерный тест сохраняет обычное нажатие; принудительное нажатие и отключение проверок не используются. Повторный CI обязателен.

Браузерные тесты используют отдельную тестовую БД и учётные записи; GPS и камера моделируются, ответы бизнес-API не подменяются. Это не проверка настоящего iPhone или production-данных.

## Что осталось до использования на сервере

1. Указать настоящие координаты и радиус действующего участка. Они не подставляются из тестовых данных.
2. После отдельного разрешения владельца установить API/web одной проверенной версии с резервной копией и обновлением nginx для защищённых фотографий. Main и production данным изменением не меняются.
3. Пройти на настоящем iPhone QR → GPS → камера → начало → результат → приёмка на реальном участке. Автоматическое распознавание личности здесь не реализовано: три кадра проверяет руководитель.

GP Service, GP Platform и GP AI Operating Platform не изменены.
