# GP Work — исправления полевого цикла, 9 сентября 2026

База: `59cfe2aa18606533beb1f970dcf92576b1fc0599`.
Ветка исправлений: `codex/gp-work-security-browser-v3`.

## Что изменено

- Единая геопроверка для прибытия на задачу и открытия/закрытия смены. Отсутствие координат участка, неизвестная погрешность, погрешность выше 50 м и выход за заданный радиус блокируют действие. Погрешность клиента больше не расширяет геозону. GPS по-прежнему является дополнительным доказательством, а не защитой от подмены координат модифицированным клиентом.
- Фотографии выдаются через авторизованный контроллер вместо публичной статической раздачи. Старые пути `/uploads/photos/...` сохраняются. Владельцу, администратору и допущенным к соответствующей работе проверяющим предоставляется доступ; постороннему пользователю — нет.
- Каждая новая загрузка получает владельца по серверной учётной записи. К своей работе нельзя прикрепить чужую фотографию. Проверка добавлена также в задачи, полив, отчёты и AI-агронома до чтения файла/отправки провайдеру.
- Аддитивная миграция `AddPhotoOwnership1732400000000` создаёт реестр файлов. Исторические фотографии получают владельца только при однозначной связи с сохранённым user ID в доказательствах. Неоднозначные файлы не присваиваются случайному человеку; старые доказательства сохраняются. Миграция не удаляет данные и не переименовывает файлы.
- Для просмотра фото браузер получает HttpOnly-cookie, действующий только на GET фотографий. Бизнес-API по-прежнему требует Bearer token. При каждом запросе проверяется активность пользователя; при выходе cookie удаляется.
- Кэш фотографий отключён в API, конфигурации nginx и PWA. Старая коллекция `gp-work-photos` удаляется при запуске новой версии приложения и выходе из аккаунта.
- «Проверка живого лица» заменена точным описанием ручной проверки трёх кадров. Руководитель видит всю тройку. Автоматическая биометрия не имитируется и не заявляется.
- Камера корректно обрабатывает отказ и пересъёмку, освобождает поток и URL предпросмотра. После успешного действия фото-контролы сбрасываются.
- При потере ответа на создание смены повторно отправляется тот же идентификатор и тот же пакет доказательств. Повтор не создаёт вторую смену и не требует повторной загрузки фото.
- Сообщения об отсутствии сети больше не предлагают рабочему запускать backend командой npm.
- Multer обновлён до 2.3.0 в API и зависимости NestJS через npm override. Чистая установка из lockfile выполнена; npm 10.8.2 подтверждает применение override. По итоговому npm audit: 0 критических, 0 высоких, 2 умеренных уязвимости в цепочке ExcelJS/uuid; они не устранены этим изменением.

Браузерная проверка проходит вход, три кадра камеры, плохой GPS, реальную загрузку фото, потерю ответа после записи смены, повторную отправку, частичный результат, возврат, исправление, ручную приёмку, просмотр защищённых фото и выход с удалением cookie и старого кэша. Только камера и геопозиция моделируются средствами браузера; бизнес-ответы не подменяются. Потеря ответа моделируется после реального выполнения запроса сервером.

Локальная вспомогательная среда: PostgreSQL 18.3/WASM через PGlite Socket, Chromium 152. Она не заменяет обычный PostgreSQL CI и проверку конкурирующих транзакций. В CI используются `postgres:18-alpine` и браузер, закреплённый Playwright 1.62.1. Разные тестовые клиенты используют отдельные IP за доверенным loopback proxy; производственные лимиты запросов не отключались.

## Что необходимо перед production

1. Разрешить публикацию только данной ветки в существующий репозиторий `talgat-maratuly/gp-work-`, запустить CI и исправить возможные отличия обычного PostgreSQL/браузера CI.
2. Проверить на настоящем iPhone камеру, отказ разрешений, QR, геолокацию и восстановление сети.
3. Убедиться, что у действующих участков заданы корректные координаты и радиусы: новая проверка намеренно не разрешит смену без геозоны.
4. После отдельного разрешения на deploy сделать резервную копию БД и файлов, применить миграцию, API и web одной версии. В действующем nginx изменить именно location `/uploads/` по новой конфигурации: сохранить существующие SSL-настройки, убрать публичное кэширование, выполнить `nginx -t` до reload. Не заменять вслепую весь production-конфиг шаблоном.
5. Обновить PWA у пользователей: старый клиент может хранить ранее закэшированные фотографии до загрузки новой версии. Ранее скачанные файлы технически нельзя отозвать.

## Граница коммерческой готовности

Эти исправления относятся к существующему приложению одной организации. Изоляция нескольких компаний в общей базе, подписки, биллинг и произвольные отраслевые настройки здесь не реализованы. Их отсутствие не означает, что внутреннее приложение GP не работает, но продавать доступ независимым компаниям в одной базе пока нельзя. Архитектурные решения и критерии находятся в `WHITE_LABEL_PRODUCT_ARCHITECTURE.md`.

Production, main и другие проекты в этом этапе не изменены. Успешную публикацию/CI/deploy этот отчёт не заявляет.
