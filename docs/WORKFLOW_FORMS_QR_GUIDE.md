# GP Work: процессы, формы по QR и приёмка

## Процесс и задача

Процесс — версионируемый шаблон дополнительных полей и согласования. Это не
планировщик автоматических задач и не замена доказательного рабочего цикла.

1. Директор или администратор открывает «Бизнес-процессы», задаёт название,
   поля, права заполнения, этапы и переходы, затем публикует шаблон.
2. На карточке шаблона выбирает «Подключить к задаче». На доске выбирает задачу.
   Переход на карточку ничего не записывает: нужно подтвердить подключение.
3. В карточке задачи руководитель видит выбранную версию. После подключения
   сотрудники заполняют разрешённые поля и нажимают доступные переходы.

Бригадир и агроном подключают шаблоны только к доступным им задачам. Роль,
завершающая текущий этап, задаётся в шаблоне. Переход проверяет обязательные поля
текущего и следующего этапа. Этап без исходящих переходов завершает процесс.
Существующие экземпляры сохраняют версию и историю; публикация не меняет их.

Процесс не создаёт задачу, не меняет исполнителя и не переводит саму работу в
статус «Принято». Новую задачу назначают в разделе «Задачи».

## Доска «Работа и улучшения»

| Статус | Реальное действие |
| --- | --- |
| Подготовить | Руководитель задаёт стандарт и ответственных; исполнитель готовится. |
| Готово к работе | Исполнитель подтвердил подготовку. Ресурсы ещё раз проверяются при старте. |
| В работе | Исполнитель начал работу через QR/GPS и экран выполнения. |
| Есть препятствие | Зарегистрирована незакрытая проблема. После устранения нужна проверка. |
| На приёмке | Отправлен завершённый результат конкретной задачи. |
| На доработке | Проверяющий вернул результат с причиной. |
| Принято | Проверяющий принял результат. |

Это вычисляемые состояния, не ручное перетаскивание карточек. «За результат»
организует выполнение и получает препятствия. «Принимает» проверяет результат;
для задачи со стандартом только назначенный проверяющий может принять/вернуть её.

«Инструмент» — выдача, возврат и состояние; «Стандарты» — подготовка, шаги и
критерии приёмки; «Причины задержек» — анализ зарегистрированных препятствий.
Последнее не является табелем, зарплатой или доказанной экономией.

## Настройки и QR

Действующая форма — `field_day_form`. В ней настраиваются поля результата каждой
задачи при закрытии смены. Снять «Показывать поле» → сохранить → обновить форму.
Скрытое поле не обязательно. Предпросмотр использует тот же компонент, что и
форма сотрудника. GPS, QR, процент и фото — отдельные обязательные шаги;
настройка дополнительных полей их не отключает.

`work_form` и `checkout_form` сохранены в БД для истории/совместимости. В интерфейсе
они доступны только для просмотра и явно названы архивными. Их настройки не
переносятся автоматически в другой рабочий цикл и не уничтожаются.

Без входа `/field/scan/:code`, `/work-form/:code` и старый
`/work-form?sectionId=...` открывают нужный участок и образец действующих полей.
Заполненные отчёты, сотрудники, задачи, координаты и фотографии не публикуются.
API возвращает только название участка/объекта, код и настройки видимых полей.
Названия, варианты и подсказки полей являются публичным содержимым; не указывайте
там персональные/конфиденциальные данные. Архивные участки/объекты недоступны.

Кнопка «Войти как сотрудник» сохраняет ссылку. Для записи смены и результатов
по-прежнему нужна личная учётная запись: QR не разрешает анонимно писать от имени
работника. У уже вошедшего работника сразу открывается его рабочий цикл; у
руководителя — просмотр. Камера/GPS не запускаются у анонимного посетителя.

## Роли и приёмка

Кабинет `/admin/director` и его пункт меню доступны только DIRECTOR.
Администратор сохраняет главную страницу и свои функции настройки. Общие API
задач/объектов не превращаются в директорские: они нужны и администратору.

В «Приёмку работ» попадают выполнения после кнопки
«Подтвердить 100% и отправить» в экране конкретной задачи. Закрытие смены само по
себе не создаёт такое выполнение: смены проверяются в «Рабочих днях».

Проверяющий видит отчёт, объём, процент, время, QR/GPS прибытия, фото ДО/ПОСЛЕ,
три кадра лица и чек-лист. Лицо проверяется вручную, это не Apple Face ID.
Для принятия нужно подтвердить лицо. Для возврата обязательна причина.
«На доработку» означает отклонение текущего результата с возможностью исправления;
отдельного окончательного отказа не добавлено. После исправления нужно новое
фото ПОСЛЕ и повторная отправка. Решение и история сохраняются.

Без назначенного принимающего действует существующий охват ролей: директор и
администратор; бригадир своей бригады; агроном по созданным им задачам. Ошибка
загрузки не показывается как пустая очередь. Решение убирает карточку из очереди,
не открывая её повторно из устаревшего состояния.
